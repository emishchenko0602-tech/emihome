## Что правилось в самой сборке

Это баги пака, не следствие настройки. Придёт свежая копия — переносить заново.

1. `send-to-telegram.mjs` падал на любом запуске: читал реестр по ключу
   `carousels`, а создаётся он с `items`. Плюс не понимал форму записи от
   `/тренды` (`title` вместо `name`, `formats` объектом вместо массива).
2. `site-deploy.mjs` умел только Vercel. Переписан на два провайдера через поле
   `provider`. Добавлен повтор проверки: на Layero контейнер поднимается по
   запросу и первые полминуты отдаёт 404 при исправной сборке.
3. `search-instagram.mjs` давал **ноль постов по всем донорам** у любого клиента
   не из AI-ниши: посты фильтруются по `NICHE.keywords`, а мастер установки это
   поле не создавал, и включался демо-список (`claude`, `anthropic`, `mcp`).
   Теперь запасной вариант — хэштеги клиента.
4. `transcribe.py`: фильтр тишины требует `onnxruntime`, тот требует Visual C++
   Runtime, которого на машине нет. Сделан необязательным. Плюс добавлен
   `condition_on_previous_text=False` — без него модель зацикливалась.
5. `reel-inbox.mjs` **нерабочий**: импортирует несуществующий `pipeline-status.mjs`.
   Вместо него написан `telegram-peek.mjs`.
6. Уроки `docs/01`, `docs/02`, `SETUP.md` переписаны с Vercel на Layero.

## Свои скрипты, которых нет в паке

| Скрипт | Что делает |
|---|---|
| `telegram-peek.mjs` | забирает накопившееся из бота, медиа в `workspace/inbox/`. Есть `--hook` для старта сессии |
| `telegram-listen.mjs` | живой слушатель, будит агента на каждое сообщение |
| `telegram-send.mjs` | ответ в бот, умеет файлы и картинки |
| `brand-stamp.mjs` | накладывает логотип и хэндл на готовые слайды |
| `photo-slide.py` | слайд карусели из настоящей фотографии, без перерисовки |
| `reel-tighten.py` | режет паузы **по замеру звука**, собирает вертикаль с субтитрами |
| `reel-broll.py` | двухслойный монтаж: фон из кадров клиента + врезка + субтитры |

**Про монтаж отдельно.** Резать надо по `silencedetect`, а не по таймкодам слов:
whisper на паузах даёт разные ответы на разных прогонах и дорисовывает
несуществующие повторы. Субтитры — только в ASS с явными `PlayResX/PlayResY`,
иначе libass считает поля в своих координатах и подпись уезжает на лицо.
В `reel-broll.py` есть проверка длины фона: без неё сломанная склейка молча
отдавала ролик со статичной картинкой.

**Вырезание фигуры по контуру доступно с 24 сентября.** Раньше `onnxruntime`
падал с ошибкой загрузки DLL, и я ошибочно объявил задачу нерешаемой. Не хватало
единственной библиотеки `vcruntime140_1.dll`; она ставится пакетом
`pip install msvc-runtime` **без прав администратора**. Урок: разбирать причину
ошибки загрузки, а не объявлять невозможным по общему симптому.

## Работа по аккаунту katerina.mi (24 сентября)

Разбор аккаунта и стратегия — `workspace/strategy/katerina-mi.md` (версия 2).
Тексты под темы — `workspace/scripts-katerina/`.

**Важный урок про данные.** Первая версия стратегии строилась на 15 постах вместо
68: `v1/user/medias` отдаёт только одну страницу, и я не проверил полноту.
Екатерина поймала ошибку. Главный вывод («вопрос в первых строках даёт 26 крат»)
на полных данных не подтвердился — держался на одном выбросе.

**Как собирать историю правильно:** `v2/user/medias` с пагинацией через
`next_page_id`, поля лежат в `response.items`, дата — **число** `taken_at`
(unix), а не строка. Плюс отдельно `v2/user/clips`. Так получается 479 постов
вместо 16.

**Правило, которого теперь придерживаться:** любую найденную закономерность
проверять снятием топ-1 выброса и медианой. Из четырёх гипотез по этому
аккаунту выжила одна.

**Что подтвердилось:** перелом в августе. Комментарии на пост 0.6 → 3.4, доля
постов с обсуждением 8% → 19%. Без топ-1 выброса 0.5 → 1.8, то есть держится.
Два поста года, вызвавшие разговор, объединяет личная откровенность, а не приём.

**Второй урок про разбор видео.** Я заявил, что в рилсах нет призыва, судя по
стоп-кадру за две секунды до конца. Призыв был — голосом, на 38-й секунде.
Разбирать ролики только по кадрам нельзя, нужен транскрипт.

## Цифры по Директу: 340 000 за КЛИЕНТА, не за заявку

Три заявки Яндекс.Директа все дошли до договора, поэтому 1 020 000 делить на

Отсюда важное для текстов: **нельзя писать «я бы не потратила туда рубля»,
опираясь на одну эту цифру** — читатель посчитает и поймает на передёргивании.
Настоящий довод другой: один клиент из трёх дал 61% оборота канала, и никто не
знает, откуда он пришёл. Без него 1 363 350 оборота при 1 020 000 затрат, и это
оборот, а не прибыль.

Ошибка пришла из собственного черновика Екатерины (`tema-05-chernovik.txt`),
я скопировал не пересчитав. Поправлено там же, в `tema-05-otpravka.txt` и в
обеих версиях продолжения.

**Правило:** получив поправку по факту, прогонять `grep` по всей рабочей папке,
а не править только тот файл, который сейчас в руках. Сегодня одна и та же
неверная цифра лежала в трёх файлах.
