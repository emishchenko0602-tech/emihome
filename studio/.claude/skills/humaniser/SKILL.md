# Антиклише-фильтр

Последний проход перед публикацией. Текст уже написан и согласован по смыслу, задача
фильтра — снять машинный почерк и вернуть живую речь, ничего не досочинив.

## Что читать

1. **`prompt.md`** — рабочий свод правил. Читать всегда, это ядро навыка.
2. **`references/patterns.md`** — каталог паттернов с примерами до и после. Открывать,
   когда непонятно, почему кусок звучит машинно, или нужен образец правки.
3. **`scripts/lint.py`** — проверка чистовика перед выдачей.

Голос автора берём из его прошлых текстов в `workspace/` (подписи, гайды, сценарии).
Текстов ещё нет — работаем по общим правилам и честно говорим об этом в конце.

## Как гонять

```
РАЗБОР → ПРАВКА → СВЕРКА → ВЫДАЧА
```

Разбор помечает места цитатами, правка переписывает каждое, сверка ищет новые клише
в своей же правке и при находке отправляет на второй круг, выдача показывает чистый
текст и таблицу «было → стало».

Перед выдачей обязательно линтер:

```bash
python .claude/skills/humaniser/scripts/lint.py <файл>
python .claude/skills/humaniser/scripts/lint.py <файл> --allow-dots   # лонгрид на сайте
python .claude/skills/humaniser/scripts/lint.py --self-test
```

СТОП в выдаче — публиковать нельзя, чиним и гоняем снова. ЗАМЕТКИ оцениваем
кластерами: одна ничего не значит, три в одном абзаце значат много.

## Границы

- смысл не меняем, меняем звучание;
- фактов не добавляем: ни цифр, ни имён, ни сроков, ни отрицаний, которых не было
  в исходнике. Это правило важнее всех остальных, потому что текст выходит под
  именем живого человека;
- структуру формата не ломаем: пришёл текст по схеме — границы шагов остаются;
- текст чистый — так и говорим, работу не имитируем.
