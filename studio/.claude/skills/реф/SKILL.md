# Разбор референса

Вход — ссылка на пост. Выход — материал, из которого делаются все форматы:
кадры, транскрипт, дизайн-код и **проверенная фактура**.

## 1. Скачай

```bash
node scripts/download-social.mjs <url> --out workspace/refs/<slug>/ --frames
node scripts/download-social.mjs <url> --out workspace/refs/<slug>/ --all      # карусель целиком
```

Только этим скриптом. Не yt-dlp, не вручную, не через сторонние сайты:
Instagram блокирует, а ручные файлы приезжают в чужих размерах и без метаданных.

## 2. Сними транскрипт (для видео)

```bash
python scripts/transcribe.py workspace/refs/<slug>/<файл>.mp4 --txt
```

## 3. Разбери структуру

По кадрам и транскрипту опиши:

- **структуру** — сколько блоков, сколько секунд каждый, где хук, где финал с призывом;
- **дизайн-код** — фон, акцентный цвет, форма карточек, шрифтовая пара, где лежит
  слово-удар. Это описание словами, а не картинка: именно оно уйдёт в промпт карусели;
- **фактуру** — что именно утверждается: названия, цифры, инструменты.

## 4. Проверь факты — это обязательный шаг, а не бонус

Расшифровка слышит названия на слух и путает их («cloud» вместо «claude»).
Автор рефа тоже может ошибаться или преувеличивать.

**Каждое название, цифру и утверждение проверь по первоисточнику** — репозиторий,
документация, страница продукта. В материал идёт то, что подтвердилось, с ссылкой.
Не подтвердилось — не идёт, даже если в рефе это главный аргумент.

Результат положи таблицей в `workspace/refs/<slug>/facts.md`: утверждение · источник · вердикт.

## 5. Отдай дальше

Скажи клиенту, что готово, и назови, что из этого пойдёт в карусель, что в гайд,
а что в ролик. Дальше — `/карусель`, `/гайд`, `/рилс`.
